# Jesterhead archive

Jesterhead, the In Flames mascot, as he appeared in *Iron Maiden: Legacy of the Beast* ("In The Dark" event,
July 2023): model, animations, effects, sounds, the three battle arenas of the event's dungeon, the enemies of its five
battles and its story. The game shut down on 31 December 2024; everything here was rebuilt from the asset cache of a phone where the
game was still installed and from the game's application package.

The extraction, the reconstruction and the site were generated by Claude (Anthropic), working in Claude Code.

```
site/      static website (viewer, character, event, notes, asset library); no build step, no CDN
sources/   full-quality exports behind the web copies in site/ (GLBs with every keyframe, PNG textures, JSON as
           exported); same paths as site/
tools/     scripts used to extract and convert the data (Python, UnityPy)
docs/      technical notes and the game shaders as decompiled from the bundles
.github/   GitHub Pages deployment of site/
```

## Run it

Any static file server works, as long as it serves `.glb` files. Opening `index.html` directly from disk does not work,
because browsers block `fetch()` on `file://` URLs.

```sh
cd site && python3 -m http.server 8000          # quick local preview
```

### GitHub Pages

`.github/workflows/pages.yml` publishes `site/` as is (no build step) on every push to `main` that touches `site/`, or
by hand from the Actions tab. To enable it: *Settings > Pages > Source: GitHub Actions*. All links are relative, so
the site works under the repository path (`https://<user>.github.io/<repository>/`) as well as on a custom domain.
GitHub Pages serves `.glb` files as `model/gltf-binary` and gzips them along with the HTML, JS and JSON.

Link previews (Discord, Slack, social networks) come from the Open Graph tags of `site/index.html`. They need absolute
URLs, which `build_site.py` writes from `SITE_URL` (the GitHub Pages address by default). With a custom domain, rebuild
the page with `SITE_URL=https://your.domain/ python3 tools/build_site.py`. The preview image,
`site/assets/social-preview.jpg` (1200 × 630), is a viewer render made by `tools/social_preview.mjs`. Discord keeps
a preview in its cache for a while after a change.

## What is in the viewer

| Part | Source | Fidelity |
|---|---|---|
| Mesh, skinning, textures, 11 animation clips | Unity bundle (AssetRipper YAML for the clips) | exact, resampled at 30 fps |
| Character shading | `RHI/BlackcombCharacter*`, compiled GLSL | ported formula (LOD 230 pass) |
| Effect timing, emissive pulses, scene dimming | `PlayParticlesWithAudio`, `TweenMaterialProperty`, `ResetTweensOnEnable`, `DirectionalLightFX`, `RotateXYZBehaviour` (IL2CPP, disassembled) | ported logic |
| 68 particle systems (+40 in the arenas) | serialized Shuriken modules | re-simulated (Unity's engine code is not public) |
| Arenas, three time periods | scene data, baked vertex colours, `RHI/BlackcombEnv*` shaders, `BlackShaderManager` | exact data, ported shaders |
| Sounds | `cso_jesterhead` character FX | game clips and volumes; mixer not reproduced |
| Battle camera and slots | APK built-in `CamerasPrefab` and `SlotsContainer` | exact |
| Take This Life cameras | `AB_TakeThisLife` cameras, `CameraManager`, the custom rig's clip, the "tap rapidly" camera's spin and drift (`RotateXYZBehaviour`, `CameraCoast`) | ported (camera flash effect not reproduced) |
| Watch chains | PhysX SpringJoint / HingeJoints | approximated with a Verlet rope |
| Enemy line-ups | read from gameplay footage (line-ups were server-side), matched to the game data | idle animation and glow pulses |

Details and the evidence behind each point: [`docs/technical-notes.md`](docs/technical-notes.md).

## Rebuilding the data

The tools expect the game's asset bundles (`Android/data/com.roadhousegames.lotb/files/ABMv6/*/b`), the APK's
`assets/bin/Data` folder and a Python environment with `UnityPy`, `numpy`, `pyyaml`, `Pillow` (plus `pyelftools` and
`capstone` for the disassembler), `ffmpeg` and ImageMagick.

1. Character: Jesterhead's bundle is `ABMv6/08892f8df03ce3add90d09f13a7e7ebc/b`; its dependencies are the bundles holding
   `CAB-6347568f…` and `CAB-547377ce…` (`67e008b0…` and `ff271c3b…` in the cache used here). Export it with AssetRipper
   (for the decompressed animation clips), then:
   ```sh
   python3 tools/build_glb.py <bundle> <AssetRipper>/ExportedProject/Assets/AnimationClip <textures_dir> sources/assets/model/jesterhead.glb
   python3 tools/export_vfx.py site/assets <bundle> <dependency bundle> <dependency bundle>
   ```
2. Arenas, sounds, game data:
   ```sh
   python3 tools/export_arena.py site/assets/arena <ABMv6> <APK>/assets/bin/Data
   python3 tools/export_audio.py site/assets/audio <ABMv6>
   python3 tools/export_event.py site/assets/event <ABMv6>
   python3 tools/export_cameras.py site/assets/cameras.json <ABMv6> <APK>/assets/bin/Data <AssetRipper export of 73d61df9…> <AssetRipper export of 08892f8d…> <AssetRipper export of <APK>/assets/bin/Data>
   ```
3. Enemies: export with AssetRipper the bundles that hold their idle clips (`a1994610…`, `317b072b…`, `ff271c3b…`,
   `ca77f608…`, `07db5788…`, `6e64738d…`, `c9da9103…`, `48bac9bd…`), then
   ```sh
   python3 tools/export_enemies.py sources/assets/enemies <ABMv6> <AssetRipper export>...
   cp -r sources/assets/enemies/lineups.json sources/assets/enemies/icons site/assets/enemies/
   ```
   It resolves each character's prefab and idle clip, calls `tools/build_character.py`, saves the battle portraits and
   writes `lineups.json`.
4. Web copies (the originals stay in `sources/`):
   ```sh
   python3 tools/optimize_glb.py sources/assets/model/jesterhead.glb --out-dir site/assets/model
   python3 tools/optimize_glb.py sources/assets/enemies/*.glb --out-dir site/assets/enemies
   python3 tools/optimize_textures.py site      # moves the PNGs it replaces to sources/
   ```
   `optimize_glb.py` drops redundant keyframes (within 1e-4 of the straight line) and the channels that stay at the
   rest pose, and re-encodes the embedded textures as WebP; renders of the original and optimised model differ by
   less than 0.1 % of the pixels. `optimize_textures.py` turns the large particle and arena PNGs into WebP and keeps
   a single copy of identical files.
5. Page: `python3 tools/build_site.py` (fills `site/index.html` from `tools/site_template.html` and makes the WebP
   display copies in `site/assets/web/`; the originals stay linked from the library). The link preview image is
   rendered from the running site with `node tools/social_preview.mjs http://localhost:8000/` (Node.js,
   `puppeteer-core` and Chrome).

`tools/il2cpp_disasm.py` annotates ARM64 code of `libil2cpp.so` with the names from Il2CppDumper's `script.json`;
it was used to read the game scripts listed in the technical notes.
